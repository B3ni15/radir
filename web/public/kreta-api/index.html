Nem hivatalos dokumentáció. A KRÉTA-nak nincs nyilvános API-ja. Ezt az oldalt a hivatalos mobilapp forgalmából és nyílt forrású kliensekből (Filc, reFilc, Firka, Radír) állítottuk össze. Bármikor változhat. Csak a saját fiókoddal használd, ne terheld a szervereket, és ne gyűjts mások adatairól.

Iskola keresése

működikGEThttps://idp.e-kreta.hu/logininstituteselector?searchValue={keresés}

Ugyanaz a kereső, ami a KRÉTA bejelentkező oldalán az iskolaválasztó mezőt tölti ki. Legalább 3 karakter kell: OM-azonosító, névrészlet vagy intézménykód. Nem JSON-t ad, hanem HTML-részletet; minden találat egy link, a data-val attribútumban az intézménykóddal:

<a … data-val="klik012345001">Petőfi Sándor Gimnázium (Budapest)</a>

Böngészős user agenttel kérd le. A régi, JSON-os intézménylista (kretaglobalmobileapi2.ekreta.hu/api/v3/Institute) már 404-et ad, lásd az elavult módszereknél.

Bejelentkezés (OAuth + PKCE)

A mobilapp ugyanazt a folyamatot használja, mint egy böngészős OAuth bejelentkezés. A felhasználó a KRÉTA saját oldalán adja meg a jelszavát, a kliens csak egy egyszer használható kódot kap vissza. Jelszót a kliensnek soha nem kell látnia.

1. A PKCE kulcspár

Minden bejelentkezéshez új code_verifier kell: egy véletlen, base64url kódolású érték (32 bájt). A code_challenge ennek SHA-256 hashe, szintén base64url, kiegészítő = nélkül (RFC 7636, S256).

2. A bejelentkező oldal megnyitása

működikGEThttps://idp.e-kreta.hu/connect/authorize
ParaméterÉrték
client_idkreta-ellenorzo-student-mobile-ios
redirect_urihttps://mobil.e-kreta.hu/ellenorzo-student/prod/oauthredirect
response_typecode
scopeopenid email offline_access kreta-ellenorzo-webapi.public kreta-eugyintezes-webapi.public kreta-fileservice-webapi.public kreta-mobile-global-webapi.public kreta-dkt-webapi.public kreta-ier-webapi.public
code_challengeaz 1. lépés challenge-e

Nyisd meg ezt az URL-t egy webnézetben. Sikeres belépés után a KRÉTA átirányít a redirect_uri-ra, ?code=…&state=… paraméterekkel. Az átirányítást a webnézetben kell elkapni: ellenőrizd, hogy a host és az útvonal pontosan a redirect_uri-é, és hogy a state egyezik.

Webnézet nélkül működik · kreta-tui

Ha nincs böngésződ (például parancssori kliensnél), a bejelentkező űrlapot el lehet küldeni közvetlenül is. Mobilappban ne így csináld: ekkor a jelszó a te kódodon megy át.

  1. Kérd le az authorize URL-t (sütikkel, átirányításokat követve). A bejelentkező oldal HTML-jéből olvasd ki a __RequestVerificationToken és a ReturnUrl rejtett mezőt.
  2. POST https://idp.e-kreta.hu/account/login form-kódolva, Referer (a bejelentkező oldal) és Origin: https://idp.e-kreta.hu fejléccel. Mezők: ReturnUrl, IsTemporaryLogin=False, UserName, Password, InstituteCode, loginType=InstituteLogin, ClientId (üres), __RequestVerificationToken.
  3. Kövesd az átirányításokat a redirect_uri-ig, és vedd ki a code-ot. Néha a válasz egy /connect/authorize/callback?… linket tartalmaz átirányítás helyett; ezt kell megnyitni.
  4. Ha az oldalon captcha (g-recaptcha) van, ez az út nem működik, a böngészős belépés kell.

Mi van az access tokenben?

Az access token egy JWT. A payloadból (a második, base64url részből) ezek kellenek:

ClaimJelentés
kreta:institute_codeintézménykód, ez kerül a szerver címébe
kreta:user_namefelhasználónév (oktatási azonosító)
roleTanulo vagy Gondviselo
namea felhasználó neve (nem mindig van benne)

Token frissítés és visszavonás

működikPOSThttps://idp.e-kreta.hu/connect/token

Ugyanaz a végpont és user agent, mint a kódcserénél, más mezőkkel:

MezőÉrték
grant_typerefresh_token
refresh_tokenaz utolsó kapott refresh token
institute_codeintézménykód
client_idkreta-ellenorzo-student-mobile-ios
refresh_user_datafalse

A válasz új access és új refresh tokent ad, a régi refresh token ezután érvénytelen. Ha a kérésre 400 jön {"error": "invalid_grant"} törzzsel, a refresh token lejárt vagy visszavonták: újra be kell jelentkezni.

Kijelentkezés

működikPOSThttps://idp.e-kreta.hu/connect/revocation

Mezők: token (a refresh token), token_type_hint=refresh_token, client_id. A hibát nyugodtan elnyelheted, a helyi tokeneket úgyis törölni kell.

Hitelesített kérések

Minden további kéréshez két fejléc kell:

Authorization: Bearer ACCESS_TOKEN
User-Agent: hu.ekreta.student/{appverzió}/{platform}/0

Például hu.ekreta.student/1.0.5/Android/0/0 vagy hu.ekreta.student/5.0.0/iOS/0. A szerver ezt a mintát várja. Ismeretlen user agentnél előfordult, hogy lassított vagy elutasított.

  • Az access token kb. 30 percig él. Érdemes lejárat előtt (pl. 30 mp ráhagyással) frissíteni, és 401-re is frissíteni, majd egyszer újrapróbálni.
  • Ha egyszerre több kérés indul, csak egy frissítés fusson. Két párhuzamos refresh közül a második már érvénytelen refresh tokennel menne.
  • A dátumok ISO 8601-ben jönnek, UTC-ben (2026-11-12T08:55:00Z), néha tört másodperccel. A lekérdezési paramétereknél elég a nap: 2026-11-09.

DKT: beadandó feladatok működik · kreta-tui

A Digitális Kollaborációs Tér (DKT) a házi és órai feladatok beadására való, saját API-val. Ugyanaz az access token kell hozzá. Forrás: kreta-tui (2026); a Radír nem használja.

Az iskola DKT-címe

GEThttps://kretadktapi-kk.e-kreta.hu/dktapi/intezmenyek/bff/url

Egy JSON szöveget ad vissza: az iskola saját DKT alapcímét (a továbbiakban {dkt}). Utána:

GET{dkt}/intezmenyek/felhasznalo/tanulo

Ebből kell az intezmenyId és a tanevId. Minden további DKT-kéréshez fejlécként is el kell küldeni őket:

IntezmenyId: {intezmenyId}
TanevId: {tanevId}

Feladatok és beadás

A {fajta} értéke hazifeladatok vagy oraifeladatok.

KérésMire való
GET /intezmenyek/tanulok/{fajta}a feladatok listája
GET /intezmenyek/tanulok/{fajta}/{feladat}/fajloka tanár által csatolt fájlok
GET /intezmenyek/tanulok/{fajta}/{feladat}/beadasa saját beadásod. Az első hívás létre is hozza („Megnyitotta” állapot), mint a weben a megnyitás.

Fájl feltöltése

  1. POST {dkt}/intezmenyek/fajlok/feltoltes/ideiglenes/proxy, multipart: fajl (a fájl) és Utvonal = DKT/{intezmenyId}/{tanevId}/{fajta}/{feladat}. Fejlécek: X-version: 3.0 és böngészős user agent; az app user agentjére a fájlszolgáltatás üres 500-at ad. A válaszban: fajlId, fajlMeretByteLength.
  2. POST /intezmenyek/tanulok/{fajta}/beadasok/{beadas}/fajlok/veglegesites: {"fajlId": …, "teljesFajlNev": "valasz.pdf", "meretInBytes": …}

Fájl letöltése

Egy fájl API-útvonala után /url-t írva (például …/fajlok/{fajl}/url) egy egyszer használható letöltési linket kapsz. Azt token nélkül, böngészős user agenttel kell megnyitni, mert a files.e-kreta.hu az app user agentjét elutasítja.

Buktatók

  • A + jel a tokenkérésben. Form-kódolásban a + szóközt jelent, ezért a refresh tokenben lévő +-t %2B-ként kell küldeni, különben invalid_grant jön.
  • User agent. A token végpont a hivatalos app user agentjét várja; mással előfordulhat, hogy elutasítja.
  • Rejtett új jegyek. Az iskola beállíthatja, hogy egy új jegy csak néhány perc múlva látsszon (ErtekelesekMegjelenitesenekKesleltetesenekMerteke).
  • Időzóna. A dátumok UTC-ben jönnek; az órarendet Europe/Budapest szerint kell megjeleníteni.
  • HTML a szövegekben. A házik, a faliújság és az üzenetek szövege HTML, \r sortörésekkel.
  • Nincs push. A KRÉTA nem küld értesítést a változásokról; időnként újra le kell kérni az adatokat. Kíméld a szervert, ne pollozz percenként.

Források

Ezt az oldalt több nem hivatalos forrás összevetéséből állítottuk össze. Ahol eltértek, a ma is működő változat került ide.

  • Radír (RadirKit, AGPL-3.0): az működik jelölésű végpontok, tesztekkel.
  • aronkv/kreta-tui (Rust, 2026): fej nélküli belépés, iskolakereső, DKT.
  • bczsalba/ekreta-docs-v3 (2022): a V3 végpontok első összefoglalója; a bejelentkezési része elavult.
  • boapps/e-kreta-api-docs: a régi v1 API leírása, ma már csak történeti érdekesség.
  • KRÉTA Ellenőrző (Postman): régi Postman-gyűjtemény.
  • manen/gokreta: Go kliens végpontlistája.
  • A Filc, a reFilc és a Firka nyílt forrású kliensei, amelyekre a Radír épül.
